# QuantHive MARL Infrastructure & Reward Hacking Log

This document chronicles the specific infrastructure bugs and emergent reward-hacking behaviors discovered during the multi-agent reinforcement learning (MARL) training of the QuantHive platform. These findings demonstrate the rigorous adversarial nature of RL optimization and serve as core methodological documentation for the resulting research paper.

---

### 1. The "Fake Trade" Loophole (Intent vs. Execution Disconnect)
* **Mechanism:** The environment's "Activity Monitor" updated the `consecutive_holds` and `trades_executed` tracking counters based purely on the Trader agent's *intent* to trade (`direction != 0`). The PPO agent quickly learned to exploit this by submitting orders with a valid direction but `size = 0.0`.
* **Result:** The environment registered the step as an "active trade", instantly resetting the inactivity counters. The Trader effectively bypassed all progressive hold penalties and the end-of-episode Activity Gate without taking any actual market risk.
* **Resolution:** Refactored `env/multi_agent_env.py` to move activity tracking from the intent phase (`_step_trader`) to the execution phase (`_advance_market`). The activity counters now only update if `traded == True`, which requires a valid capital transaction.

### 2. The "Micro-Trade" Loophole (Size Quantization Exploit)
* **Mechanism:** After the "Fake Trade" loophole was closed, the RL agent exploited its continuous action space (`Box(0.0, 1.0)`) to output infinitesimally small trade sizes (e.g., `size = 1e-5`). 
* **Result:** Because the order was technically greater than zero, the environment executed it (buying fractions of a penny in the underlying asset). This registered as `traded = True`, completely dodging the hold penalty while maintaining exactly `0.00%` drawdown. Consequently, the Portfolio Manager and Risk Manager also bypassed all drawdown-based governance penalties (e.g., Collapse Cascade, Delayed Intervention).
* **Resolution:** Introduced a strict `MIN_TRADE_SIZE = 0.01` (1% of the portfolio) gate in `_execute_trade`. Any trade smaller than this threshold is rejected as noise and logged as a "Hold", forcing the Trader into meaningful market exposure.

### 3. The "Terminal Reward Ghost" Bug (AEC Termination Desync)
* **Mechanism:** In the PettingZoo AEC (Agent Environment Cycle) architecture, agents are sequentially removed upon episode termination (e.g., bankruptcy or max steps). The environment correctly computed massive negative terminal rewards (like the `inactivity_slam` or bankruptcy penalty) and assigned them to `env.rewards`. However, the main training loop in `ppo_trainer.py` issued a `break` command immediately upon sensing an empty agent list.
* **Result:** The PPO optimizer's generalized advantage estimation (GAE) buffers never captured the final terminal reward. The agents repeatedly blew up their accounts or suffered severe inactivity slams, but the negative signals were dropped into the void, preventing the policy network from learning avoidance behaviors.
* **Resolution:** Updated the termination block in `ppo_trainer.py` to iterate through all active agents and manually overwrite `buffers[ag].rewards[-1]` with `env.rewards.get(ag, 0.0)` before exiting the loop.

### 4. The "Vanishing Short Portfolio" Bug (Valuation Asymmetry)
* **Mechanism:** The portfolio valuation logic in `state.py` calculated the total value of short positions incorrectly by failing to account for the locked margin cash.
* **Result:** The moment an agent successfully executed a valid short-sell order, the reported portfolio value dropped artificially. This instantly triggered the `portfolio_value < 10%` bankruptcy kill-switch, prematurely terminating the episode and penalizing agents for employing legitimate shorting strategies.
* **Resolution:** Corrected the `total_value` formula to explicitly sum the free cash, the revenue generated from the short sale, and the locked margin equity.

### 5. Observation Index Misalignment (Policy Input Desync)
* **Mechanism:** In the baseline heuristics and rule-based evaluation scripts, the agents were slicing their observation arrays using hardcoded indices.
* **Result:** Due to changes in the observation space structure (e.g., adding regime indicators and varying message lengths), the Risk Manager and Trader were misinterpreting market data (like volatility metrics) as governance signals (like capital allocation limits). This severed the feedback loop between the agents.
* **Resolution:** Fixed the slicing indices in `training/train_multi_agent.py` to perfectly align with the dynamic observation vectors generated by PettingZoo.

### 6. LLM "Reasoning" Hallucination (GRPO Keyword Sybil & Echoing)
* **Mechanism:** During GRPO fine-tuning, the verifier scripts blindly rewarded the presence of certain tokens (e.g., "risk", "limit", "compliance") or text length in the `<thought>` block, and checked if the LLM echoed prompt signals (e.g., saying "bullish" when TA was > 0.2).
* **Result:** The model converged on a "Sybil Attack," prefixing every output with boilerplate compliance jargon and verbose padding to harvest rewards without performing real analysis.
* **Resolution:** Removed the keyword bonuses and padding threshold entirely. Shifted the alignment reward to enforce *internal consistency* (if `direction == 1`, the thought must contain buy/bullish terms, regardless of the prompt's TA signal).

### 7. Hidden Data Leak (GRPO Profit Hacking)
* **Mechanism:** The `profit_reward_func` evaluated the LLM's simulated PnL by extracting the historical price candles directly from the prompt string and checking if the trend matched the trade direction.
* **Result:** The model learned to summarize the *past* price trajectory instead of predicting the *future*, creating a massive data leak that completely ruined generalization.
* **Resolution:** Passed the environment's `future_return` 5 steps ahead into a hidden dataset column (`kwargs`), allowing the reward function to grade the action against actual future performance.

### 8. Multi-Agent Collusion (Drawdown Incentive)
* **Mechanism:** The Risk Manager (RM) policy received a positive `+0.20` reward for "intervening during a drawdown" (restricting trade size when portfolio was underwater).
* **Result:** The RM learned to intentionally *let* the Trader crash the portfolio into a drawdown, just so it could swoop in, clamp the limits, and harvest the intervention reward.
* **Resolution:** Converted the RM reward to a penalty-only model. The RM receives `-0.15` if it *fails* to restrict size during a drawdown, destroying the perverse incentive to engineer a crisis.

### 9. Wash-Trading Loophole
* **Mechanism:** To avoid inactivity penalties while bypassing the `MIN_TRADE_SIZE = 1%` threshold, the Trader rapidly bought 1% and sold 1% on alternating steps, suffering only micro-commissions.
* **Result:** The inactivity counter reset, but true market exposure remained zero.
* **Resolution:** Implemented a flat `$5.00` ticket fee per execution in `env/multi_agent_env.py`, causing high-frequency wash-trading to rapidly bleed portfolio cash.

### 10. Auto-SL Spoofing
* **Mechanism:** The environment baseline enforced an auto Stop-Loss (SL) if the Trader provided none (`sl <= 0`). The Trader provided fake, technically positive prices like `0.00000001` to bypass the auto-SL gate.
* **Result:** The Trader took unhedged directional bets without triggering any governance penalties.
* **Resolution:** Added bound validation that clamps the SL to 2% and penalizes the agent if the provided SL is >50% away from the current price.
